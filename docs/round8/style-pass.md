# 旧菜谱改文风

以前的菜谱多数是 GPT 起草的。事实和用量大体没问题，毛病在文风：读起来像工艺文件或审稿报告，不像一个会做饭的人在讲。这一轮只改文字，不改做法。

通用规范见 `~/Projects/knowledge-compiler/style.md`，本页只列菜谱里最常见的毛病。下面的例句都出自站里的旧稿，只用来说明毛病是什么样子；改的时候按每道菜自己的内容写，不要照搬这里的改法。

## 要改的

1. **工艺文件的词**：停点、阶段、进入下一段、初步熟化、建立底味、获得足够热量、目标状态、口径、另计、指令、执行、确认是否。换成做饭的人会说的话。
   - 旧：三个阶段各有停点：糖红褐而不焦黑，鸡肉中心熟透，汁能挂皮而锅底没有烧干。
   - 新：炒糖色、焖、收汁，各有一个该停手的样子：糖炒到红褐色，鸡翅焖到熟透，汁收到能挂在翅皮上。
2. **防御性的补充**：一步做完后再补一句澄清，例如“这里是初步熟化，稍后还要回锅”“暂时沉底正常”“不把秒数当成停火指令”“泡发等待另计”。读者照着做不会误会的，就删掉；确实会误会的，改成一句顺口的提醒，放在那一步动作之前。
3. **反驳没人提的误解**：“不能把汁水变稠都解释成炒糖色”“香料只能改变气味组合，不能恢复变质原料”。删掉，或者只说正确的那一面。
4. **把动作压成名词**：肌肉失水、调味分散、受热凝固的程度。改回“谁做了什么”：肉一直炒，水分就被挤出来。
5. **元叙述**：“这里用……做家常版本”“这份做法”“本版本”。只有这道菜真是变体（加了奶油、换了肉）时，开头说一次是哪个版本；其余删掉。
6. **重复的检查和告诫**：每一步都写“约 20 秒起检查”“不足就继续，再检查”。改成看得见的状态：“炒 20 秒左右，肉丝全部变白就倒汁。”熟度温度全文只写一次，写在判断熟没熟的那一步，写成一句自然的话：“温度计插进最厚的一只、避开骨头，到 74°C 就熟了。”
7. **不新鲜的原料**：“有腐败异味的直接弃用”这类话删掉，整条讲变质原料的要点也删掉；`## 要点` 只讲做菜时会出的错。删了以后要点不能少于 2 条：少了就把剩下的某条拆开，或者从步骤里挑一个常见失误补上，不要编。
   - 例外：贝类、蟹、小龙虾这类要买活的，“壳不闭合、煮后不开口的挑出来扔掉”是做菜的一步，保留。剩饭剩菜怎么存、多久要扔（有具体时间的）也保留。泡发木耳、银耳、米制品这类有中毒风险的泡发和存放时限也保留。
8. **开头两段**：第一句说这道菜吃起来是什么样（软、脆、汁多还是干香），第二句接它靠哪条原理成立。不要一上来就是“用 A、B 和 C 建立……”。

## 不能动的

- front matter 一个字都不改。
- 所有数字原样保留：用量、分钟、秒、温度、尺寸、个数，包括“2–3 分钟”这样的范围。数字可以挪到同一步里更顺的位置，但不能删、不能改、不能合并。
- 每步里可观察的状态（“由浑转亮”“竹签能顺畅插到中心”）保留，可以换更顺的说法。
- `## 步骤` 的步数不变，每步的动作和先后不变；`## 要点` 每条仍是 `- **症状**：原因（链接原理）。补救或预防。`
- 正文里的链接（`/principles/...`、`/recipes/...`）全部保留，链接文字可以改得更顺。
- 不加新的事实、新的数字、新的个人经历。拿不准的说法不要改成更肯定的说法。
- 正文长度保持在 600–1000 字（不含空白）。

## 怎么判断改好了

大声读一遍：像一个会做饭的朋友站在灶台边跟你讲，就对了。
